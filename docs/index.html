The backend owns its costs.
The Python occurrence index uses linked positions, live pair sets and a lazy max-priority heap. Only edges next to a replacement change. Snapshot positions are visited left to right, skipping overlaps invalidated by earlier replacements. Stale heap entries are checked against current counts.
Initialization, pair sets, sorted occurrence snapshots, heap pushes and stale pops all cost work and memory. Optional traces copy rows and all pair counts. The browser uses fresh full recounts and has no heap counter claim. Structural differences do not imply measured speed, memory savings or a universal complexity guarantee.
Exact merge parity preserves the original tokenizer artifact and encode/decode behavior. It does not improve a language model, make the simplified split GPT-2 compatible or establish semantic compression quality.
BPE and incremental pair maintenance are established work, credited to Gage, Sennrich and colleagues, and later implementation literature. This is an engineering backend, not a new tokenization algorithm.
